# 视频节点台词口型功能设计

日期：2026-09-01
状态：已通过用户评审

## 背景与目标

当前视频节点生成的视频没有人声。用户希望为视频节点增加"台词"能力：给视频节点提供人物台词文本，生成的视频中人物开口说出这些台词，且口型与台词同步。

经确认的需求结论：

- 台词来源**两者都要**：视频节点上手写台词输入框 + 一键"✨ 提取台词"（从提示词/上游故事文本中提取）。
- 语音生成方式：**由视频模型直接生成**（台词注入提示词，Agnes 自己生成人声与口型，类似 Veo3 做法），不走 TTS。
- 实现方案：方案 A（台词字段 + 提示词注入），保持最小改动。

## 关键约束与风险

- Agnes Video 2.5 Flash 已知参数中没有显式的"台词/对口型"参数，模型直生语音能力**未确认**。因此实现前必须先做能力实测（Phase 0），实测不支持则停下向用户汇报，不继续建 UI。
- Agnes 官方文档站不可访问（doc.agnes-ai.cn 不存在，搜索 API 403），能力边界只能实测。

## Phase 0：能力实测（先于一切 UI 工作）

用 curl 直接调 Agnes `/videos`（text 模式，AGNES_API_KEY 取自环境），提示词带对白指令，例如：

```
一位年轻女性面向镜头微笑，开口说出台词："你好，欢迎来到这里"，人声清晰，口型与台词精确同步
```

生成后下载视频确认：是否有人声、口型是否开合。根据实测结果：

1. 支持人声 → 确定最终注入话术（可能需要调整措辞/中英文）。
2. 不支持人声 → 停止，向用户汇报实测结果，讨论改走 TTS 音频参考（已有链路）或其他途径。

实测脚本为一次性脚本（bash + curl + 轮询），不进代码库。

## 数据模型

`types/agnes.ts` 的 `CanvasNodeData` 新增：

```ts
/** 视频节点：人物台词，生成时注入提示词由模型直生语音 */
dialogue?: string;
```

节点 data 随图整体持久化，无需改 db/存储层。

## 后端：`/api/text/format` 新增 `extract-dialogue` action

在 `FORMAT_ACTIONS` 中新增（结构与现有 6 个 action 完全一致）：

- key：`extract-dialogue`
- label：`提取台词`
- system：你是影视台词提取专家。从用户的视频提示词或故事文本中提取人物说的话，整理成可直接口播的中文对白。要求：只保留人物说出的内容，去掉叙述、动作、场景描写；格式为"角色：台词内容"，多个角色分行；台词自然口语化，可直接朗读；直接输出台词本身，不要任何解释、引号或前后缀；中文，80 字以内。

请求体、路由逻辑均不变（`model` 可解析且非 Agnes 走 `genericTextGenerate`，否则走 `createAgnesChatCompletion`）。

## 生成链路：台词注入提示词

`lib/store.ts` 的 `triggerGeneration` 视频分支，在现有"参考图一致性描述"后缀处理之后、发起请求之前：

```ts
const dialogue = data.dialogue?.trim();
if (dialogue) {
  prompt = `${prompt}\n人物开口说出台词（人声清晰，口型与台词精确同步）："${dialogue}"`;
}
```

注入话术以 Phase 0 实测结论为准（此处为初版）。

## UI

### 视频节点卡片（`components/VideoNode.tsx`）

提示词 textarea 下方新增一行紧凑台词输入：

- 单行 `<input>`（placeholder "人物台词（可选）"），绑定 `data.dialogue`，`nodrag`。
- "✨ 提取台词"小按钮，样式沿用 ✨ 优化按钮（`text-[10px]` 紫色系），提示词为空时禁用；提取中禁用并显示 busy 态。

### 配置面板（`components/NodeConfigPanel.tsx`）

视频配置区新增台词区块：

- 多行 `<textarea>`（2 行高），绑定 `data.dialogue`。
- "✨ 提取台词"按钮（`text-[11px]` 紫色系），与卡片行为一致。

### 提取调用（两处共用逻辑）

POST `/api/text/format`，body：`{ text: 节点生效提示词, action: "extract-dialogue", model: data.textModel }`。生效提示词 = 本节点 prompt，为空时回退上游文本节点 prompt（与生成链路 `lib/store.ts:161` 的取值一致；卡片/面板内按现有 upstream 读取方式计算）。

- 成功：结果直接写入 `updateNodeData(nodeId, { dialogue: result })`。
- 失败：在按钮旁显示错误文字（`textError` 风格的局部 state），不写入。
- 不使用预览弹窗（台词很短，直接填入）。

## 错误处理

- 提取接口失败：沿用现有 500 + `{ error }` 结构，UI 显示错误文字。
- 提示词与上游文本均为空：提取按钮禁用。
- Agnes 不支持语音：Phase 0 实测拦截，不会带病上线。
- 台词注入是纯文本追加，对不支持语音的模型无害（最多被当作提示词描述忽略）。

## 测试与验证

1. `npm run build` 零 TypeScript 错误。
2. Phase 0 实测报告：Agnes 是否生成人声、口型是否开合（附视频确认结论）。
3. 部署后手工验证：
   - 视频节点手写台词 → 生成 → 视频有人声且口型开合。
   - 提示词含对白 → 点"✨ 提取台词" → 台词框填入口播对白 → 生成同样生效。
   - 上游文本节点提供故事 → 提示词为空时提取仍可从上游文本提取。
   - 台词为空时生成的请求与现在完全一致（无追加）。
   - 文本模型选非 Agnes 模型时提取仍可用（generic 路由）。

## 不做（YAGNI）

- 不做多人分角色配音管理、音色选择、台词时间轴对齐。
- 不做 TTS 回退自动链路（TTS 音频节点已存在，可手动连接）。
- 不建独立台词节点类型。
- 不做英文台词输出切换。
